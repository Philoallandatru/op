# 双评后的匿名裁决

两份匿名初评均已冻结。以下决定在组别映射启封前作出，依据是题面、答卷原文、事先约定的判据和对应规范页。评审在 20/24 份上使用了相同四档标签。其余 4 份存在会不会改变现场处置的分歧，另有 3 份仅在逐项分数上出现分歧。

| 匿名卷 | 裁决 | 影响判断的证据 |
| --- | --- | --- |
| R587808 | 可能误导。C1、C2 各 1，C3 为 0.5 | 保持缓冲所有权正确。末尾却说未取到记录时“读仍在飞或待延迟中止，继续等待”。题面只说未保存，轮询线程可能已消费目标完成；目标也可能以普通 I/O 错误结束。该分支会漏掉核对已消费记录和向应用交付错误的动作。 |
| R792607 | 可能误导。C1、C2 各 1，C3 为 0.5 | 作废交错 VPD 样本、串行重读取证均可执行。VPD 乱码时直接按 Identify SN 入账，却未证明槽位、VPD 资产标识与 NVM 子系统序列号的对应关系。标明来源仍不足以证明登记在正确对象名下。 |
| R999928 | 可能误导。三项各 1 | 两秒内第二次按键取消移除，等待平台放行的关键项均答对。额外下达必须按 NVMe 的 CC.SHN/CSTS.SHST 确认关机的要求。混合背板题面没有确认设备的储存协议，且拔除许可由实际插槽、软件和业务下线流程产生。这会给正确的 PCIe 移除流程加一个不适用的硬门槛。 |
| R544252 | 可能误导。C1、C2 各 1，C3 为 0.5 | 正确要求 RP Busy 清零。恢复后 VID/DID 有效仅能证明当时该地址有响应，仍不足以锁定先前的全 F 源自 UR、证明设备身份连续，进而直接按原设备绑定。把清状态位并入“只读”同样会改变现场证据。 |
| R448194 | 可能误导。三项各 0.5，触发预设否决项 1 | 能说明 Saved 的回退和 Current 的读义。实际结案却从能力受支持、Saved=Default 推断没有成功保存。真实已保存的值可以等于 Default，这一推断同时损害了对读数语义的解释。 |
| R866607 | 可能误导。三项各 0.5 | 能说明回退路径。随后的分支预设维护脚本写的值等于当前 Y，既没核对请求中的实际值，也没排除后来又被更改，造成历史写入与当前读数必须一致的假矛盾。 |
| R418688 | 可能误导。C1、C3 各 0.5，C2 为 0 | 开头知道单个 Success 不足，随后又称只有非 Success 才能是最后一个 Completion，形成矛盾。未交代超时后部分已返数据可保留或丢弃；即使正确拒绝把它当整段，也不满足这项独立判据。仅凭 AER 位清零派给 SSD 内部同样超出观测。 |

**引文勘误。** SSD-F3-04 的冻结评审包中，NVMe PDF 第 221 页关于 Saved 回退的原文位于 Figure 192（Get Features CDW10）；Figure 193 在同一页说明 CDW14。英文锚点、页码、题面、分数判据均正确，两位评审均以原文含义判卷。冻结包保留初版定位，后续题库和工作台采用更正后的图号。[第 221 页](https://nvmexpress.org/wp-content/uploads/NVM-Express-Base-Specification-Revision-2.1-2024.08.05-Ratified.pdf#page=221)
