# 五份高分答卷的结果与现场处置

从上一轮候选组逐份抽取同时满足三项的答卷：返回过至少一张金标页、严格评分通过、全文评审未达到原样可用。共五份，其中一份需修改、四份可能误导。下列“处置”是按工单目标给出的工程判断；引用的规范支撑结果含义和适用条件。原答、真实取证和原评语见[上一轮候选答卷](../../reports/field-usable-v2.json)。

## 1. 换盘前的长测结果，SSD-OPS-09，100 分

原答把“DSTR=2h 或其他非 0h”全部送去重跑。NVMe Base 2.1 的 Figure 212 在同一页分别定义 DSTC（测试类型）和 DSTR（测试结果），两个字段都可能取 2h。先以设备、时间顺序和类型确认最新结果对应本轮 extended 自测。DSTOS=0h 时应忽略进度百分比。只取到表头、没有本轮结果时，先取回并保存 RDS1，验收保持待定。[Figure 211，PDF 第 239 页](https://nvmexpress.org/wp-content/uploads/NVM-Express-Base-Specification-Revision-2.1-2024.08.05-Ratified.pdf#page=239) · [Figure 212，PDF 第 240 页](https://nvmexpress.org/wp-content/uploads/NVM-Express-Base-Specification-Revision-2.1-2024.08.05-Ratified.pdf#page=240)

| 本轮 DSTR | 结果的含义 | 工单如何处理 |
| --- | --- | --- |
| 0h | 完成且无错 | 身份及类型都匹配时，记录本轮长测通过。 |
| 1h | 自测命令导致中止 | 对齐主机命令记录；若仍需完整长测，先安排无冲突窗口。 |
| 2h | 结果字段编码为控制器级复位中止 | 保全条目，核对测试类型、控制器和复位时序。若已确认是本轮扩展自测，这与 §8.1.7.2 规定的跨复位继续要求冲突，应列为异常调查。 |
| 3h | 命名空间从清单移除导致中止 | 核对命名空间变更，确认本次验收对象后再决定补测范围。 |
| 4h | 处理 Format NVM 导致中止 | 核对维护记录和目标，待相关操作完成后安排所需测试。 |
| 5h | 执行中发生致命或未知测试错误，未完成 | 留存结果及有效诊断字段，调查测试为何停止；自动重跑会掩盖首发信息。 |
| 6h | 已完成，有失败段，段号未知 | 记录长测失败，保留日志并进入失败分析。此值下应忽略 SEGN。 |
| 7h | 已完成，至少一个段失败 | 记录失败，并保存 SEGN 标明的首个失败段。其他诊断字段逐项看有效位。 |
| 8h | 原因未知的中止 | 保留日志和同期主机记录，标记原因待查。 |
| 9h | Sanitize 导致中止 | 关联已有维护事件，分开记录消毒与长测结果，待环境稳定后再安排所需长测。 |
| Ah–Eh | 本版保留 | 保存原始字节，核对版本和解码；不由该值推断介质状态。 |
| Fh | 空条目 | 查找与本轮相符的有效记录；仍缺则记录“缺本轮结果”。 |

Figure 212 是通用结果表。具体到题面的扩展自测，§8.1.7.2 规定它应跨控制器级复位保留并恢复。旧参考答案允许见 2h 后直接安排普通补测，漏了这项约束。已修订日后使用的参考答案、否决项与追问分支，保留原评审版本。Figure 211 给的最后一个字节偏移为 563，完整结构长 564 字节；只读 RDS1 时只需覆盖它的字节范围。[扩展自测，PDF 第 520 页](https://nvmexpress.org/wp-content/uploads/NVM-Express-Base-Specification-Revision-2.1-2024.08.05-Ratified.pdf#page=520) · [冻结旧题](self-test-case-as-tested.jsonl) · [修订后的维护题库](../../scenarios/maintenance.jsonl)

## 2. 持续轮询时中断少，SSD-IO-08，85 分

原答提出先提交再停写 CQ Head Doorbell，可能在观察窗开始前已消费全部工作，还把一次及时到达归因于定时器重启。先撤销按 TIME 判盘失败的验收项。TIME 是推荐值，门铃活动可推迟后续通知。对照应保持相同队列、向量和合并配置，预留 CQ 空位，使停写门铃的观察窗内确有新待通知 CQE。[NVMe §5.1.25.2.2，PDF 第 428 页](https://nvmexpress.org/wp-content/uploads/NVM-Express-Base-Specification-Revision-2.1-2024.08.05-Ratified.pdf#page=428) · PCIe §6.1.4.5，PDF 第 500 页

| 观测结果 | 下一步 |
| --- | --- |
| 窗内没有新待通知 CQE，或 CQ 无可用槽 | 本轮没有测到通知条件。修复复测前提，保留原来已确认的业务成功结论。 |
| 有新 CQE 且实际看到 MSI-X | 可以记录这次通知到达。用同时序的门铃活动对照判断关联；单次到达不能证明控制器内部重启过计时器。 |
| 有新 CQE，主机未收到通知 | 同步核对目标向量的屏蔽、链路上的 MSI-X 写和主机投递。链路已发则沿投递路径查；抓取覆盖充分仍未见发送才查控制器通知条件。PBA=1 结合屏蔽时序说明有待发事件，PBA=0 也不能倒推从未发过。 |

## 3. L1.2 设置顺序与唤醒，SSD-PWR-03，90 分

原答把“两板顺序相同”当成转查电气的分支，两板可以有同一处违规。题面已抓到违规写序。按两端支持能力，在 ASPM L1 关闭期间先配置适用的时序和阈值，再按 Downstream Port、Upstream Port 的顺序置对应使能。测试时恢复允许 ASPM L1 的配置，采到实际 L1.2 进入与退出。PCIe §5.5.4，PDF 第 488 页

| 观测结果 | 下一步 |
| --- | --- |
| 任一板仍使用违规顺序，或只有最终寄存器值 | 先纠正并记录写序。两板值相同不足以放行。 |
| 配置正确，未观测到目标 L1.2 周期 | 标记本次未覆盖故障条件，补状态轨迹。 |
| 配置正确且实际进入 L1.2，仍复现 | 对齐退出轨迹、时钟、供电和板级时序，再评估物理根因。 |
| 有效覆盖下未复现 | 报告负载、次数、覆盖和未复现结果；偶发故障的一轮阴性结果不足以确认唯一根因。 |

## 4. 移动活动 CQ 的 PRP List，SSD-IO-06，85 分

原答指定操作 SQ3。SQ 的 CQID 决定其完成去向，SQ 和 CQ 的编号可以不同，多个 SQ 可以指向同一 CQ。先从成功的建队记录或驱动映射列出所有关联 SQ，在授权的维护窗口停止新提交并处置在途工作。队列空闲本身未结束活动 PRP List 的寿命。[NVMe §5.2.1，PDF 第 441 页](https://nvmexpress.org/wp-content/uploads/NVM-Express-Base-Specification-Revision-2.1-2024.08.05-Ratified.pdf#page=441) · [CQID，第 443 页](https://nvmexpress.org/wp-content/uploads/NVM-Express-Base-Specification-Revision-2.1-2024.08.05-Ratified.pdf#page=443) · [Delete I/O CQ，第 444 页](https://nvmexpress.org/wp-content/uploads/NVM-Express-Base-Specification-Revision-2.1-2024.08.05-Ratified.pdf#page=444)

| 对目标 CQ 的结果 | 下一步 |
| --- | --- |
| 当前关联集合未知，或仍有 SQ 关联 | 保持旧表和内存，按实际关联解除依赖，不能据 CQ3 的编号选 SQ。 |
| 对应 Delete CQ 成功 | 可以回收旧 PRP List。需要迁移时用新表建 CQ，再恢复实际受影响的 SQ，验证其 I/O。 |
| 命令专属状态 01h，队列标识无效 | 核对控制器实例和 CQID，再查对象当前状态；错误返回未证明本次删除成功。 |
| 命令专属状态 0Ch，删除无效 | 检查是否仍有关联 SQ；查实际关系，不能凭它断定某个 SQ 或在途命令是根因。 |
| 其他错误、超时或未取得此次完成 | 保存 SCT/SC 和命令上下文，维持原映射；独立核实对象生命周期。已确认的控制器复位也是规范定义的边界，题面未发生复位，也未授权以复位作探针。 |

## 5. 三个 CQE 与一个 MSI-X，SSD-IO-11，85 分

原答称三条 CQE 正常就可关闭工单，又把非成功状态和缺失完成并作同一种故障。每向量的 pending 位无法计数，单条通知可提示多个新完成。已匹配三个 SQID/CID，下一层要查对应的驱动消费、命令状态以及最终回调。优先用已有 trace，手动 drain 会改变消费状态。PCIe §6.1.4.5，PDF 第 500 页 · [NVMe §3.3.1.2，PDF 第 108 页](https://nvmexpress.org/wp-content/uploads/NVM-Express-Base-Specification-Revision-2.1-2024.08.05-Ratified.pdf#page=108)

| 每个命令的证据 | 下一步 |
| --- | --- |
| 新 CQE 状态成功，匹配的最终回调也成功 | 可以关闭该命令的交付疑点。三个命令都满足才可报告三笔均成功交付。 |
| 收到带错误状态的 CQE | 该命令已完成并携带错误。按 SCT/SC 诊断，同时验证错误是否正常传递给调用方。 |
| CQE 已匹配，回调缺失或未记录 | 查驱动消费及向上交付的时间线。缺日志时保留未知；未交付时沿主机路径定位。 |
| 新记录与已抓到的三个 CQE 不一致 | 用同一时间窗、队列实例、phase 与标识复核。单条 MSI-X 或稍后的一次队列快照均不能推翻已记录的完成。 |

## 旧题回归的判法

在独立盲测投放结束后，使用同一冻结候选和预算，各复问上述五题一次。分别核对原来指出的那条缺陷是否仍会导致错误操作；答复能够直接解决提问时，可省略不影响决定的编码。若出现不同的现场错误，另列说明。回归由一位已知历史问题的评审检查，结论单列，不并入新题的原样可用率或误导率。
