# 第七轮处置条件留出试验

复盘第六轮的六份需修改答卷，沿同题对照、草稿、工具结果和复核包定位。两道退步题分别丢了远端能力有效位的清除条件，以及请求可因超时结束的路径。PMR 答卷保留了联合门槛，旧评审包未展示一条实际有规范支撑的附加描述。保留原标签以便追溯。[六份答卷复盘](six-answer-audit.md)

## 对照设置

两组均使用 Pi、DeepSeek Flash 起草、Codex Sol 复核、相同语料和检索排序。每次交卷总时限 120 秒，8 次取证含两次预取。基线是第六轮候选。新配置用 `read_spec_conditions` 返回英文字段周围的原文和相邻页续行。复核包按 PDF 页装入完整摘录，优先保留直接字段证据。最终输出逐项交付必要的前提、备选路径和恢复门槛，并继续核对历史主张的同期观测。[冻结配置](registration.json) · [处置条件 skill](../../skills/conditions/ssd-field-decisions/SKILL.md)

16 道模拟工单来自第六轮结束后的 16 个新故障族，NVMe 和 PCIe 各 8 道。入组前核对了 35 处真实规范定位。按题交叉安排两版顺序，保留第一次计划会话。两位模型对匿名答卷独立评分，裁决后才揭盲。C2 在投放前固定为必要条件，缺少任何一个关键前提或备选路径均不得满分。该指标以计划提问为分母，与原样可用、误导分别计算。[题面](questions.jsonl) · [评审口径](review-protocol.json)

两组均交齐 16 份。候选的 SSD-F7-12 曾报 Windows MCP 缓存写入冲突，此后仍成功进行两次实时取证并交卷。主统计保留首答，并单列移除此题后的同题结果。

## 结果

| 指标 | 第六轮配置 | 第七轮配置 | 排除运行告警题后的对照 |
| --- | ---: | ---: | ---: |
| 处置条件完整 / 计划 | 13/16 | 16/16 | 12/15 → 15/15 |
| 原样可用 / 计划 | 10/16 | 16/16 | 9/15 → 15/15 |
| 可能误导 / 交卷 | 0/16 | 0/16 | 0/15 → 0/15 |

6 道题转为原样可用。关键条件从部分或未满足转为完整的三题是 Enhanced Controller Metadata 的操作例外、PMR 的持久屏障，以及 Hierarchy ID Pending 的两种清除路径。3 道历史题的原样可用数为 1/3 → 3/3。两位初评在 26/32 份上给出同一标签。6 份判据或标签分歧经过揭盲前裁定。一批无效的初评格式使用同一模型分别补齐，已验证的初评保留。候选成功调用字段取证 16 次，中位答题耗时从 29.2 秒升至 49.4 秒。结果来自这批模型盲评工单。[指标明细](metrics.json) · [基线答卷](baseline-reviewed.jsonl) · [候选答卷](candidate-reviewed.jsonl) · [匿名裁定](ratings-final.jsonl)
