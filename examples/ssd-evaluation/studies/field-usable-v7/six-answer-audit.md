# 第六轮六份需要修改的答卷

将候选首答、实际工具返回、交卷复核收到的原文、未修改的草稿和第五轮配置的同题答卷对齐。`SSD-F6-02`、`09`、`11` 是从原样可用转为需修改的三题。历史盲评保留原判。[原答与评审](../field-usable-v6/candidate-reviewed.jsonl)

| 题 | 条件在哪一步出问题 | 修订后的交接依据 |
| --- | --- | --- |
| SSD-F6-02 · PMR 就绪 | **退步。** 同次 EN=0、NRDY=0 的禁止写和 EN=1 且 NRDY=0 的恢复门槛都保留了。新增的未就绪写请求正常结束却不更新内存，也确实出现在 NVMe PDF p.614 和复核包里。原判把未展示给评委的支撑当成无法核实，属于评审证据缺口。 | 保留联合门槛。写请求的附加表现虽有条款支持，但不必用于决定本次是否放行。 |
| SSD-F6-09 · 远端 Data Link Feature | **退步。** 草稿提到进 DL_Inactive 清除有效位。把证据交给复核时只有新交换的确切规则，PCIe p.799 命中片段没带上清除行，复核也没保留该条件。 | 把进入 DL_Inactive 清 Valid 和重新交换后置 Valid 一起给出。现存位图只能证明新一轮。 |
| SSD-F6-11 · Transactions Pending | **退步。** 草稿与复核包均有 PCIe p.556 的超时路径。最终只写 FLR 结束必须清位，漏掉未完成请求也可经 Completion Timeout 终止。Device Status 定义跨 pp.731–732，现场答复应按 Endpoint 解释。 | 保留成功完成、超时终止及 FLR 清位，判定历史成功靠同次请求的 Completion。 |
| SSD-F6-04 · NOPPME | 旧轮次实时工具启动失败，但 NVMe p.405 预取已包含允许后台操作临时超限和最后工作态上限。复核只保留了清零分支，删掉了会影响旧峰值判定的例外。 | 清零与开启两条规则一起写。只在相应当时生效的设置、后台操作和功耗证据齐备时作历史判断。 |
| SSD-F6-05 · Notice 起点 | p.399 出现在搜索页列表里，开关时条件为真也会发事件的原句没有到复核。答案只用 AER 的交付机制解释。 | 写明开启已成立条件即可触发通知。起点最迟已在开启时，精确起点需要更早的同期证据。 |
| SSD-F6-07 · CDQ 发布 | p.518 的段落只返回初值和首次发布部分，未覆盖多次写入条目时最后才更新 CDQP 的原句。 | 同时核对创建初值、首次发布以及多次写入的最后更新，再按现场已满足的平台同步条件读取。 |

新增字段取证会随命中返回同页附近原文，并展开边界续页。复核按页装入完整摘录，优先传入针对字段的结果。输出逐条列出已核实的判定条件，保留必要的并列前提、超时和恢复路径。历史归因仍须经过同期证据核对。正式留出题中，C2 冻结为关键处置条件，评委按完整支持给满分，显示分母为全部计划题。

六道旧题均用最终配置复跑。新版保留了 DL_Inactive 清 Valid、Completion Timeout 终止、NOPPME 的开启例外、Notice 开启时的现存条件、CDQP 的最后写入，以及 PMR 的两个联合门槛。部分复跑也加入了范围以外的技术细节，例如 PMR 的健康状态码。这些复跑记录核对了所缺条件，独立留出得分使用另外的 16 道题。[六份回归首答](six-case-regression.jsonl)
